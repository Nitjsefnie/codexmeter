Design spec · Codexmeter · 2026-08-11

Parse Claude-format GPT transcripts without replacing existing parsers

Context
Claude Code sessions served by claude-code-proxy are routed to the Codex bucket while retaining Claude Code JSONL and key layout. Codexmeter already detects and deliberately leaves them unstamped. This design makes them first-class inputs.
ScopeAdditive parser
MetricsFull parity
BackfillAutomatic
Native pathsPreserved
Decision

Build a dedicated Claude-format adapter and normalize both archive layouts into the existing ingest pipeline.

Adapt Claudit’s mature behavior onto Codexmeter’s shared records, pricing, persistence, and rollups. Do not import another checkout at runtime and do not fold another large parser into backend/parse.py.

01

Goals and boundaries

Everything the new format can truthfully provide, with no regression to existing formats.

  • Ingest new and previously skipped main/subagent transcripts, plain or XZ.
  • Produce usage/cost, context turns, substantive prompt count, tool calls/errors, churn, visible text size, reply latency, and rate-limit hits.
  • Trust message.model; the current GPT transcript records gpt-5.6-sol.
  • Keep the archive slug as stable project ID and use a consistent absolute cwd as display label.
  • Do not import /root/claudit, move objects, replace native parsers, or invent alias-to-model mappings.
02

Why this approach

Chosen

Dedicated adapter

Independent deployment, format-focused state, shared Codexmeter contracts, fixture-proven parity.

Rejected

Runtime Claudit import

Less copied code but creates a cross-checkout deployment dependency and mismatched pricing/schema contracts.

Rejected

Inline copy

Quickest edit but tangles detection, legacy Kimi parsing, and Claude state in one module.

03

Architecture and data flow

parse_file stays the single detector; ingest stays one pipeline.

1Scan

Recognize native and Claude key layouts.

2Normalize

Produce project/session/main candidate metadata.

3Dispatch

Codex → Kimi → legacy → Claude precedence.

4Adapt

Walk Claude lines into shared output fields.

5Persist

Reuse canonicalization, rollups, and invalidation.

Adapter state

Claude-specific state owns request-ID max merging, iteration flattening, replay detection, prompt boundaries, tool IDs, latency anchors, and candidate cwd values. Shared helpers own billing rows, tool rows, context turns, cost, and error resolution.

Archive identity

Native sessions/<project>/<session>/wire.jsonl behavior is unchanged. For <project-slug>/<session>/...jsonl[.xz], the first two components define project/session; a basename equal to the session ID marks the main file. Nested data/subagent files are peers.

06

Error handling

  • Malformed JSON lines remain skippable.
  • Deterministic parse exceptions remain ingest failures and never stamp a file as parsed.
  • A valid format with no usage persists as a truthful empty session rather than “unsupported.”
  • Unknown models keep the explicit estimated-price fallback.
  • Absent or conflicting cwd falls back to the project slug.
  • Skip accounting remains available for future recognized-but-unsupported formats.

08

Risks and mitigations

Port driftAnchor behavior with named Claudit-derived fixtures; never import the checkout at runtime.
Native regressionPreserve precedence and exact existing fixture assertions.
MispricingTrust payload model IDs, test known GPT models and unknown fallback.
Duplicate recordsKeep within-file request merge and cross-file canonical UUID handling.
Large first ingestReuse bounded fetch chunks and sequential persistence; no all-at-once backfill.
